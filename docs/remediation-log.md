### Issue REM-01: Frontend TypeScript Compilation Failure (TS2339)
- **Issue ID:** `REM-01`
- **Severity:** P1 (Build / Packaging Blocker)
- **Affected Subsystem:** `frontend/src/components/campaign/CampaignLaunchDrawer.tsx`
- **Root Cause:** When `CampaignLaunchDrawer.tsx` was enhanced to preserve `slo_id` and `min_sample_count` during payload creation (lines 170 and 174), the TypeScript interface `CampaignLaunchDrawerProps.initialSLO` was not updated to declare those optional fields. Invoking `npm run build` failed during `tsc -b` with:
  ```
  src/components/campaign/CampaignLaunchDrawer.tsx:170:34 - error TS2339: Property 'slo_id' does not exist on type '{ p95_ttft_threshold?: number; max_error_rate?: number; itl_p95_threshold?: number; throughput_floor?: number; constraints?: any[]; }'.
  src/components/campaign/CampaignLaunchDrawer.tsx:174:25 - error TS2339: Property 'min_sample_count' does not exist on type '{ p95_ttft_threshold?: number; max_error_rate?: number; itl_p95_threshold?: number; throughput_floor?: number; constraints?: any[]; }'.
  ```
- **Reproduction:** `npm run build --prefix frontend`
- **Proposed Fix:** Add optional fields `slo_id?: string;` and `min_sample_count?: number;` to `CampaignLaunchDrawerProps.initialSLO`.
- **Files Modified:** `frontend/src/components/campaign/CampaignLaunchDrawer.tsx`
- **Diff:**
  ```diff
  --- a/frontend/src/components/campaign/CampaignLaunchDrawer.tsx
  +++ b/frontend/src/components/campaign/CampaignLaunchDrawer.tsx
  @@ -43,6 +43,8 @@ interface CampaignLaunchDrawerProps {
     initialSLO?: {
  +    slo_id?: string;
       p95_ttft_threshold?: number;
       max_error_rate?: number;
       itl_p95_threshold?: number;
       throughput_floor?: number;
  +    min_sample_count?: number;
       constraints?: Array<any>;
     } | null;
  ```
- **Verification Result:** Executed `npm run build --prefix frontend`. Build succeeded in 1.74s with 0 errors. Executed `npm test --prefix frontend`: all 28 unit tests passing.
- **Side Effect Assessment:** Purely additive interface typing; zero runtime side effects.

### Issue REM-02: Missing Applied Configuration in Published Report
- **Issue ID:** `REM-02`
- **Severity:** P2 (Diagnostic / Reporting Defect)
- **Affected Subsystem:** `src/slokern/api/routes/campaigns.py`
- **Root Cause:** In `campaigns.py:206`, `winner_config` was retrieved from `all_search_configs`, which holds the pre-execution candidate definitions generated by `_make_config()`. In those objects, `effective_settings` is `{}` because the adapter has not yet applied the configuration. When `build_report_artifact()` was invoked at line 355, it received `winner_config` with empty effective settings, causing `report.md` Section 1 to render `- **Applied Settings:** {}`.
- **Reproduction:** Inspect `artifacts/experiments/cmp-8a020d00/report.md` line 16.
- **Proposed Fix:** When ranking selects a winning candidate, locate the matching executed `run_res` in `run_results` and populate `winner_config.effective_settings`, `parameter_status`, and `environment_fingerprint` from `run_res.applied_config`.
- **Files Modified:** `src/slokern/api/routes/campaigns.py`
- **Diff:**
  ```diff
  --- a/src/slokern/api/routes/campaigns.py
  +++ b/src/slokern/api/routes/campaigns.py
  @@ -205,6 +205,14 @@
           winner = ranked[0] if ranked else None
           winner_config = next((c for c in all_search_configs if winner and c.candidate_id == winner.candidate_id), None)
  +        if winner and winner_config:
  +            winning_run = next((r for r in run_results if getattr(r, "applied_config", None) and r.applied_config.candidate_id == winner.candidate_id), None)
  +            if winning_run and winning_run.applied_config:
  +                winner_config = winner_config.model_copy(update={
  +                    "effective_settings": winning_run.applied_config.effective_settings,
  +                    "parameter_status": winning_run.applied_config.parameter_status,
  +                    "environment_fingerprint": winning_run.applied_config.environment_fingerprint,
  +                })
  ```
- **Verification Result:** Executed `pytest tests/unit/api/ -q`: all 73 tests passed in 50.85s. Executed `ruff check src/slokern/api/routes/campaigns.py`: 0 errors.
- **Side Effect Assessment:** Safely copies runtime read-back data into the report model; no impact on search selection logic or execution flow.

### Issue REM-03: UI Acceptance Screenshot Provenance Discrepancy
- **Issue ID:** `REM-03`
- **Severity:** P1 (Audit & Evidence Integrity Finding)
- **Affected Subsystem:** `docs/final-ui-acceptance-report.md`, `artifacts/screenshots/ui-acceptance/`
- **Root Cause:**
  1. The automated test script `frontend/test_ui_acceptance.cjs` ran at 5:24–5:26 PM and launched campaign `cmp-52d90003`.
  2. Because the test script expanded the drawer's 4-input custom accordion without modifying unexposed secondary constraints (`itl_ms <= 15.0ms`, `throughput >= 50 tok/s`), all candidate configurations breached constraints and evaluated as `INCONCLUSIVE`.
  3. Consequently, no candidate was selected as winner, and Run 6 (verification rerun) was never dispatched in `cmp-52d90003`.
  4. The test script's condition to take screenshot 05 (`state.isVerificationRun`) never triggered, leaving a stale screenshot from `cmp-73e93672` (captured at 3:33 PM) on disk.
  5. Screenshots 06, 07, 08, 09, and 10 captured `cmp-52d90003` showing `INCONCLUSIVE`, `Selected Candidate: None`, `PENDING (NOT YET RECORDED)`, and `UNVERIFIED`.
  6. Campaign `cmp-8a020d00` was subsequently executed at 5:32 PM with calibrated constraints, successfully verifying winner `95db015e9de9`. However, the UI screenshot script was not re-run.
  7. The author of `final-ui-acceptance-report.md` claimed 10/10 passed and cited screenshots 01–10 as proof of `cmp-8a020d00`, which directly contradicted the physical images.
- **Remediation Action:**
  1. Preserved original 10 screenshots in `artifacts/screenshots/ui-acceptance/` completely untouched and fully mapped their provenance in `docs/final-ui-acceptance-report.md`.
  2. Executed zero-GPU acceptance run via `scripts/run_zero_gpu_acceptance.ps1` with Edge headless targeting `cmp-8a020d00`.
  3. Captured 5 fresh physical screenshots into dedicated directory `artifacts/screenshots/ui-acceptance-cmp-8a020d00/`:
     - `01-tuning-lab-winner-95db01.png` (renders winner `95db015e9de9`, WINNER tag, 48 tok/s)
     - `02-experiments-history-6runs.png` (renders 6-run campaign history)
     - `03-verification-view-verified.png` (renders `run-verify-69a57759`, VERIFIED verdict, drift metrics)
     - `04-reports-view-cmp-8a020d00.png` (renders report `rep-128a1ce7`, LIVE badge, INDEPENDENT VERIFICATION PASSED)
     - `05-workloads-view.png` (renders workloads specification controls)
  4. Updated `docs/final-ui-acceptance-report.md` criteria UI-04, UI-06, and UI-08 to VERIFIED based on physical screenshot evidence.
  5. Zero GPU compute consumed; zero changes to historical JSONL data.
- **Verification Result:** Fully verified by `@ui-auditor` and `@release-verifier`. All 10 UI criteria now proven with physical evidence.
